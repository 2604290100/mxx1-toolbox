## 2026-10-06 晚七（右键菜单的先后顺序：顺序其实是 Windows 按键名排的）

用户一句「**右键增强后的右键菜单顺序文字效果图发我看下，我需要调整一下顺序**」——
他要的"效果图"是**真实菜单里的先后**，不是设计稿；随后拍板：

按"不替用户往菜单里加东西"的底线，要他自己点一次「装上常用功能」；
键名第 5 位已经留好）和「**换名做进「启动修补」，自动换顺序（不用我点装上）**」。

- **先量，再改**。用 shell 自己那套接口（`SHParseDisplayName` → `IShellFolder::GetUIObjectOf` /
  背景位置用 `CreateViewObject` → `IContextMenu::QueryContextMenu` → 遍历 `HMENU`，**纯只读**）
  把真实菜单按顺序打出来，四个位置 4/4 一致 —— 那一版是
  「一键解除占用 / 复制文件名 / 复制文件路径 / 在此处打开终端 / 解除文件占用」：
  **「解除文件占用」因为键名 `Mxx1Unlock` 的 `U` 排最后，一直在最底下**。
  又做了一次**对照实验**（临时文件类型 + 四条假键：`Aaa1Test` 标题写「探针Z」、
  `Zzz9Test` 标题写「探针A」、`Mxx1Toolbox.0.Probe`、`Mxx1Unlock`，跑完立刻删干净）：
  结果「探针Z」在最前、「探针A」在最后、`Mxx1Toolbox.0.Probe` 排在 `Mxx1Unlock` 前 ——
  **顺序由键名决定，标题完全不参与**；按标题（汉字码位）排的假设也被排除
  （「在此处打开终端」该在「复制…」前面，实际在后面）。教训写进 `PITFALLS.md` **坑 39**。
- **改法：键名带序号** `Mxx1Toolbox.<n>.<名字>`（1 CopyName / 2 CopyPath / 3 Unlock /
  4 AutoUnlock / 5 Common / 6 Terminal）。**以后改顺序只改这个数字**。
  界面「右键增强」页的**段序故意没跟着动**（用户只要求改菜单里的顺序 —— 页面是按功能分段的）。
- **顺序必须有机器可读的出口**：`rightmenu items` 新增 `verbs=` / `legacy=` 两行，`titles=` 改按
  菜单顺序报；回归 **M46/M47/M47b** 把"序号 1..6 = 用户定的顺序"钉死（谁改名字里的数字 =
  改用户菜单里的顺序，测试当场红）。人眼核对用新增的**只读探针 `tools\Show-MenuOrder.ps1`**
  （把真实菜单按顺序打出来，工具箱六项打 ★，一个字节都不写）。
- **老用户自动换名**（用户要的）：新增 `MigrateLegacyNames`，走启动修补（`SyncIfInstalled`）和

  （反了会让他短暂甚至永久少一项）；不是我们写的同名键一个字都不动；这一项本就不该在的位置上的
  旧键直接清掉；旧键的记录一并摘掉。`IsInstalled` 改成**新旧两个键名都问** ——

- `rightmenu status` 会说清楚：某项已装（新旧名字都算）+ 一行
  `上一版的键名　还有 N 处在（菜单顺序还是老的）—— 打开一次工具箱就会自动换成新键名`。
- **测试**：M 组 +5（**M46/M47/M47b** 顺序钉住、**M44** 重写成"旧键名迁移 + 第一稿残渣清"、

## 2026-10-06 晚五（提示卡定成 5 秒 + 两个新右键项：复制文件路径 / 在此处打开终端）

  实测 `自己关掉用了=4.9 秒` / `点完到关掉用了=42ms`。
- **「复制文件路径」**（`src\CopyPath.cs`，CLI `copypath`，右键菜单第四项，只装 2 个位置）：
  唯一的难点是**多选**。注册表静态 verb 拿不到整个选中列表，`MultiSelectModel=Player` 按微软文档
  是"一次把选中的都传进来"，**可这条我们在真实资源管理器里一次都没实测过**（§14.10 挂着人眼确认）。
  于是不赌：单个路径进来时先记进**批次文件**，**轮询到"文件不再变、而且最后一条就是我"**才由
  最后一个进程把整批复制出去 → 两种调用模型都对。
  ⚠️ **第一版"追加完死等 400ms"当场被自己的测试抓住**：三个并发进程**被切成两批**
  （`#1 closer count=1 / #2 waiter / #3 closer count=2`，剪贴板里只剩 2 行）——根因是每个进程都要
  冷启动一次 .NET + WinForms，到达时间能差一秒多。改成轮询后 `#2 closer count=3`、剪贴板三行齐全。
  **"等文件不再变"比"等一个拍出来的毫秒数"稳**（和 §12.60 那条教训同源）。
  取舍写进正本：批次文件不删、按"上次写入距今 > 1.5 秒"判新旧，所以**两次独立复制挨得比 1.5 秒还近
  会被并成一批**（多一行看得见，丢一个文件是静默的 —— 选前者）。
