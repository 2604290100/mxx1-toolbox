## 2026-10-06 晚三（第一个新工具：文件哈希校验 + 「说明文案」两层）

用户贴了一份《UX 体验强化版说明文案》—— 10 个新工具，每个三段（面板简介 / 悬停提示 / 详情完整说明），
末尾一句：**「你给我看一下做一个最简单的功能看一下，你修改后的开发速度」**。

- **挑功能的理由**（不是挑最炫的，是挑最能被验的）：三个候选里选「文件哈希校验 MD5/SHA256」——
  它是唯一**能用现成的独立实现交叉验证**的（PowerShell 的 `Get-FileHash`：另一套算法库、
  另一套读文件代码），而且不动注册表、不写用户文件、不要管理员、没有多屏 / DPI 坑。
  屏幕取色器看着更炫，但要现场调多屏与遮罩层，自动回归只能验前半截 —— 不适合当"速度样本"。
- **方案先给用户看**（他说「你先给我方案不要动手做」），方案里只留两个要他拍板的点。
  他拍板：**做哈希校验**；**「面板简介」那一层不做**。于是文案落成两层：
  `hint`（悬停一句）+ **新增 `about`**（右键「功能说明…」窗口里的整段详情）。
- **正文只有一个拼装处**（`MainForm.HelpText`）：说明窗口和 `tip <id> --full` 打同一份字符串，
  所以"窗口里写了什么"可以被自动断言；清单规矩交给 L0 体检（有 `about` 必须有 `hint`、
  `hint` ≤ 120 字；**只写一半的说明比不写更糟**）。灵敏度验过：摘掉 `hash-check` 的 `hint` →
  当场 `FAIL hash-check`。
- **工具本身**：`FileShare.ReadWrite`（正在被别的程序写着的文件也能算）、一趟读完同时喂 MD5 与 SHA256、
  后台线程 + 进度百分比（窗口不假死）、拖文件进窗口、粘"网站上给的值"对比、**不猜算法**
  （32 位按 MD5、64 位按 SHA256，认不出就说认不出，不拿"不一致"吓人）。
  CLI `hash <文件> [--expect=]` 用**同一份** `HashTool`，退出码 0/1/2 是契约。
- **顺手修的**：① `Launcher.DescribeCommand` 补 `ModuleApp` 分支 —— 原来程序自己的窗口在说明里
  显示的是 `内置动作: app/newtool` 这种给排查问题看的话；② `Test-Gui` 的 C01d 在只挑 C 组跑时会
  假红（它读的灰按钮墨迹是 B 组量的）→ 改成 `Skip`，不许把"没测到"记成失败。
- **这一轮顺带把两笔老欠账一起清了**：完整界面回归在"工具箱关着"的条件下 **161 通过 / 0 失败**。
- **速度**（用户要看的就是这个）：L0（编码 + 内联体检）**3.2 秒**、编译 **1.7 秒**、
  新加的 T 组 27 项 **2.9 秒**、C 组 19.2 秒、完整界面回归 161 项约 2.7 分钟。
  **没有再出现"改一处就被拖去跑全套"** —— 挑组 + 闸门那次提速（上一轮）在这里第一次真正兑现。
- 设计正本：`docs\DESIGN.md` **§12.59**（含两条界面自动化的实测教训，也记进了 `PITFALLS.md` 第 33 条）。

## 2026-10-06 晚二（标题栏加「最小化」）

用户原话：**「给工具箱右上角添加一个最小化，目前很影响体验，只有关闭的情况下」**。

- 动手之前先用探针把**标题栏**量清楚（`%TEMP%\mxx1-cap\Probe.cs`：五个变体各截一张图，再用
  `WM_GETTITLEBARINFOEX` 读每个按钮的矩形与状态）。实测结论：`Min=true / Max=false` 的窗口，
  系统一定会画一个**灰掉、点不动的最大化方框**（`max state=0x1` = unavailable），
  而 `Min=false / Max=false` 时那一格根本不存在 —— 这是 `xxxDrawCaption` 从 Win95 起就有的规矩，
  不是 WinForms 的 bug。也就是说「有最小化」和「标题栏没有灰方块」**不能同时满足**，
  除非自绘标题栏。
- 两条路都算过账：① **让最大化真能用** —— 按钮墙是固定 4 列、列宽不随窗口变，最大化之后墙缩在
  左上角、右边和下方一大片空白，而且 `WndProc` 的 `WM_EXITSIZEMOVE` 分支与 `RememberGeometry`
  会把铺满屏幕的尺寸写进 `settings.ini`，**冲掉用户记住的窗口大小**；② **自绘标题栏**
  （`FormBorderStyle.None` + 自己画 "— ✕"）—— 要接管拖动、八向缩放、贴边、DWM 阴影、
  DPI 与 Win7 那一路。**把两边的对比截给用户看之后，他拍板：「只要最小化，那个灰方块留着」。**
- 落地：`src\MainForm.cs` 一处 `MinimizeBox = true`（`MaximizeBox` 仍是 `false`，
  注释里写明"别为了藏灰方块把它改成 true"）；`docs\DESIGN.md` 的窗口表、§10 红线第 3 条改写，
  新增 **§12.58** 记这次取舍与实测表格；界面回归 `A03` 从"**没有**最小化方框"反过来断言"**有**"，
  新增 **A03b/A03c**（真发一次 `SC_MINIMIZE` → `IsIconic` 必须为真 → `SW_RESTORE` 还原，
  位置与尺寸一字不差）。界面 **151 → 153 项**，合计 **360 项**。
- 顺手清掉了上一轮那笔欠账：**在"工具箱关着"的条件下跑完整界面回归 = 153 通过 / 0 失败**
  （N21b、B10/B11 改成"环境不满足就 Skip"之后的第一次全绿）。
- **这一轮第一次真用闸门，就抓到闸门自己的三个毛病**（第一个是**静默**的）：
  ① **读 git 改动永远读成空** → 每次都报"自动读不出改动"→ **静默退回全套跑**（表面"宁多勿少"很安全，
  实际把 `tests\test-map.json` 整个架空，给出的原因还是误导的）。根因是 PowerShell 5.1 的坑：
  `$ErrorActionPreference='Stop'` 下，**原生命令写到 stderr 的每一行都是终止性错误**，`2>$null`
  也拦不住 —— 而 git 只要工作区里有 CRLF 差异就会写 CRLF warning，于是命令中断、`$LASTEXITCODE`
  变成 `-1`。修完补了**真跑自检**（假 git 先往 stderr 写一行 warning、再往 stdout 报一个文件名；
  用 AST 把那个函数抠出来、在子进程里带 `Stop` 跑）—— **灵敏度也验过**：把防线摘掉立刻 `COUNT=0`。
  ② **每一段测试的输出被 `[void](…)` 一起吞掉**：跑两分钟屏幕上一片安静（像卡住），失败时只剩
  一句"闸门没过"，没有任何细节可查。③ **假欠账" A14 没跑"**："没跑的组"用的 `-notcontains`
  没跟前缀匹配（`-Only A` 会连带跑 A14）对齐。三条的根因与修法都记在 `docs\DESIGN.md` **§15.3**，
  坑写进 `PITFALLS.md` **第 31 条**。
- 紧接着用户问 **「刚刚耗时最长的步骤是什么，感觉很浪费时间！」**，把账摆出来一看确实离谱：
  界面全量 145.7 秒，闸门跑了 3 次（111 / 126 / 131 秒，里面各套一遍命令行全量 102.5 / 115.3 / 118.0 秒），
  **合计约 8 分 34 秒，而真正需要的只有「命令行 A,B,D,E,H + 界面 A 组」，约 7 分钟是白花的**。
  白花在三个地方：① 第 1 次是闸门自己坏了（静默退回全套）；② 第 2、3 次是**规则太粗** ——
  一条 `tests/* + tools/Test-*.ps1 → 两个套件都全套`，改一个**界面**测试文件也拖出整套命令行；
  ③ 我自己连着跑了两遍闸门，界面那半又选了全量去清欠账。
  修法（都做完并实测，正本 `docs\DESIGN.md` **§15.5**）：① **映射按套件收口**（改界面测试 → 126 → **6.2 秒**；
  改 `src\MainForm.cs` → 约 126 → **26 秒**）；② **闸门"刚跑过就跳过"**（同一套输入 30 分钟内跑通过 → 套件
  跳过，只跑 L0 + 编译：同一条命令连跑 **26 → 6 秒**）；③ **"为什么跑全套"打在明面上**。
  另外把"改映射表 = 跑全套"这条废规则删了 —— 两个套件**根本不读映射表**，跑一万遍也验不出它的错
  （那一跑 115 秒纯属仪式）；换成闸门自己的**覆盖率自检**（每个组都要被某条规则够得着，前缀匹配；
  灵敏度验过：删掉 `P` 组 → 当场 `[FAIL]`）。
  两个实现坑也记了：指纹**不能算 exe**（csc 每次写新 PE 时间戳 → 永远不命中）、指纹要在 **L0 + 编译之后**算
  （`-Fix` 补 BOM 会改时间戳）；顺带 `[int]$SwitchParameter` 会抛异常，得用 `.IsPresent`（坑 32）。
