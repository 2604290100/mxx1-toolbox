## 0. 先读这几条，否则做出来的东西合不进去

**你是在改哪个项目**：`D:\萌新工具开发\toolbox\` —— 「萌新工具箱 / mxx1 Toolbox」，
一个 Windows 按钮墙启动器。界面上是一格一格的按钮，每个按钮点下去启动一个程序 / 脚本 / 工具箱自己的窗口。
技术栈是 **C# WinForms + .NET Framework 4.x + 系统自带的 `csc` 编译**（不开 Visual Studio），
语言版本锁 `/langversion:5`（**不能用 C# 6 以上的语法**：不能用 `$"…"` 插值、不能用 `?.`、不能用表达式体成员）。
支持 Windows 7 SP1 / 10 / 11。

**改代码之前必须先读**：`skill\mxx1-toolbox\SKILL.md`（简短，必读）、
`docs\DESIGN.md`（设计正本，长，按需查）、`CHANGELOG.md` 顶部。

### 0.1 七条会**静默**毁功能的红线

1. **编码**：所有 `.cs` / `.ps1` 必须是 **UTF-8 带 BOM**；`.json` / `.md` **不带 BOM**。
   多数补丁工具会**静默丢掉 BOM** → 改完任何文件都跑一遍 `tools\Test-Encoding.ps1`
   （加 `-Fix` 自动补）。BOM 掉了的 `.ps1` 会被 PowerShell 5.1 当 GBK 读，报一堆看不懂的语法错。
2. **不许把本机绝对路径写进代码**：`.cs` / `.ps1` / `.json` 里出现 `D:\…`、`C:\Users\你的名字\…`
   这类字面量，编码体检查会直接判 FAIL。要用 `%SystemRoot%`、`%USERPROFILE%` 占位符
   （`src\Launcher.cs` 运行时展开）或 `Environment.GetFolderPath(...)`。
3. **界面四条硬规则**：① 按钮行只能用 `LayoutButtonRow()` / `LayoutButtonRowRight()` 排，不许手写坐标；
   ② 标签绝不与按钮重叠（重叠会吃掉鼠标点击，按钮"点了没反应"）；
   ③ 主窗口 `MinimizeBox = true` / `MaximizeBox = false`，**其它窗口两个都 false**；
   ④ 界面文字别用 `✓ ⚠ →` 这类字形（微软雅黑没有这些字形，会显示成方框）。
4. **会改动系统的新动作必须先过 `MainForm.EnsureAccepted()`**（用户同意《使用条款》）。
   命令行不拦，但要在日志里留痕。
5. **危险动作默认温和**：删除一律**先进回收站**（`Microsoft.VisualBasic.FileIO.FileSystem.DeleteFile`
   带 `RecycleOption.SendToRecycleBin`），要永久删除必须显式再确认一次；
   清单里配 `"confirm": true`。**不允许**出现"批量卸载 / 一键关闭安全防线"这类按钮（合规底线，有测试盯着）。
6. **文案两层，别只写一半**（本项目已定的口径，用户明确**不做**"面板简介"那一层）：
   - `hint`：鼠标悬停那一句，**单行、按 ≤110 字写**（ToolTip 不换行，太长会顶出屏幕；
     L0 体检的上限是 120 字，界面回归 `H05` 按 110 字卡，所以按 110 写最稳）；
   - `about`：右键「功能说明…」或选中按钮按 `F1` 弹出的窗口正文，**多行、用 `\n` 分段**，
     写法参考已经做完的 `hash-check`（见 `tools\system.json` 第 27 行）；
   - **有 `about` 就必须有 `hint`**（只写一半的说明比不写更糟），反之可以。
     这条由 L0 体检自动卡（`tools\Test-InlineSyntax.ps1`），不用你记，写错了会红。
   - 正文只有**一处**拼装：`MainForm.HelpText`（界面窗口和 `tip <id> --full` 打的是同一份字符串，
     所以"窗口里到底写了什么"能被自动断言 —— 别在窗口里另拼一份）。
7. **新窗口一律继承 `Mxx1Form`**（`src\Theme.cs` 附近 / 见 `src\HashTool.cs` 的 `HashForm : Mxx1Form`）：
   主题、字体、DPI、窗口位置记忆都在基类里，自己 `new Form()` 会跟其它窗口长得不一样。

### 0.2 干活的规矩（用户亲口定的，别违反）

- **一次只做一个功能**，做完就交，别顺手重构别人的功能，别"顺便优化"。
- **只测你动的那一块**：每个功能开自己的测试组，跑自己那一组（几秒～几十秒）。
  **全套测试只在你交卷给用户之前、或用户明确要求时跑一次**，日常不要跑（全套要好几分钟，用户嫌浪费时间）。
- 提交信息写**四段**：`改了什么` / `为什么` / `我验了什么` / `我没验什么`。
  最后一段必须诚实写"没验的"，这是本项目的硬约定。
- **`git push` 和发版本都要先问用户**，本地提交可以直接做。
- 界面类改动**必须自己看一眼真窗口**（截图 / 探针），只跑自动化不算验过。
  读 `skill\mxx1-toolbox\PITFALLS.md` 第 33 条：UI Automation 报 WinForms 按钮的
  **矩形是错的**（实测报 1488,536，真实位置低 180px），照着它点等于点空 ——
  本项目验界面统一用 `EnumChildWindows` + `WM_GETTEXT` + `GetWindowRect` + `PostMessage(BM_CLICK)` + 真鼠标。

**"加一个程序自己的窗口"标准七步**（每一步都别省）：

1. 写 `src\你的窗口.cs`：`内部逻辑`（纯函数、好测）+ `XxxForm : Mxx1Form`（界面）。
   逻辑与界面分开，命令行才能复用同一份逻辑（哈希工具就是这样：窗口和 `hash` 命令算的是同一份）。
2. `tools\xxx.json` 加按钮：`kind=builtin`、`module=app`、`action=你的动作名`、`hint`、`about`。
3. `src\MainForm.cs`：`RunTool` 的 switch 里加 `case "你的动作名": Open你的窗口(); break;`
   （不加就会走 `default:`，界面上只留一句"未实现的界面动作"）。
4. `src\Program.cs`：加 `case "命令名": return XxxCommand(args);` + `Help()` 里加用法两行。
5. `tools\Make-Icons.ps1`：加映射 + 需要的形状，重跑生成 `assets\icons\你的按钮id.png`。
6. 测试：`tests\Test-Cli.ps1` 新开一组（字母见 §2 末尾），`tests\test-map.json` 加规则。
7. 文档：`CHANGELOG.md` 的 `[未发布]` 段、`docs\DESIGN.md` 加一小节、`README.md` 与 skill 的计数。

**只加一个脚本型按钮**（不写 C#）要简单得多，只要 3 步：清单里加 `kind=script` + `inline`、
`tools\Make-Icons.ps1` 加图标、测试里补断言。**能用脚本解决的别写 C#。**

### 2.1 复制文件路径（最简单，建议拿它热身）

- **按钮**：`tools\system.json`，`tab: system`，`segment: 4`（修复与诊断），`order: 90`，
  `id: copy-path`，`name: 复制文件路径`，`kind: script`，`shell: powershell`，`timeoutSec: 60`。
- **行为**：用 `System.Windows.Forms.OpenFileDialog`（`-Multiselect`）或系统"选择文件"框选一批文件 →
  把完整路径一行一个复制进剪贴板 → 弹一张提示卡（`src\Balloon.cs` 的 `NoticeForm`，跟着鼠标、
  几秒自消，别用系统托盘气泡。
- **命令行**：`copypath <文件…> [--quote]`（`--quote` 每行加英文引号，方便粘进命令行）。
  退出码 0 成功 / 2 用法错。
- **边界**：路径里可能有中文和空格（要 `-LiteralPath`）；长路径 >260 字符要说明"系统限制"；
  剪贴板被别的程序锁住时重试 3 次再报"剪贴板忙"。
- **可选**（做之前问用户）：另装一个 HKCU 右键菜单项「复制完整路径」，
  现成机制在 `src\RightMenu.cs`（照 `rightmenu unlock.on` 的写法，**只写 HKCU、不要管理员**）。
- **hint 草稿**：`选几个文件，把它们的完整路径复制到剪贴板（一行一个）`
- **about 草稿**：
  `把文件的完整路径复制出来，方便粘到命令行、聊天窗口或者文档里。\n用法：点这个按钮 → 选文件（可以多选）→ 路径已经复制好了 → 去要用的地方粘贴。\n只读文件列表，不改动、不移动任何文件；路径里有空格时会按你选的格式加引号。`

### 2.3 当前目录打开终端

- **按钮**：`tools\system.json`，`segment: 3`（进程 · 信息 · 链接），`order: 40`，
  `id: open-terminal`，`name: 打开终端`，`kind: script`，`shell: powershell`，`timeoutSec: 60`。

- **命令行**：`terminal [<目录>] [--wt] [--cmd]`（不给目录就用当前目录）。
- **边界**：目录不存在要报错别硬开；路径里有空格 / 中文 / `&` 要正确引号；

### 2.4 无效快捷方式清理

- **按钮**：`tools\cleanup.json`，`segment: 3`，`order: 20`，`id: broken-links`，
  `name: 无效快捷方式清理`，`kind: builtin`，`module: app`，`action: brokenlinks`。
- **窗口**：扫描 **桌面 + 开始菜单**（当前用户 + 所有用户，四个目录）里的 `.lnk` →
  解析目标（`IShellLink` COM，或 `WScript.Shell` 的 `CreateShortcut`）→ **目标不存在**的列出来 →
  勾选 → 「删除到回收站」（拒绝永久删除）。
- **命令行**：`brokenlinks [--delete] [--json]`，默认**只列不删**。
- **边界（这几条最容易做错）**：
  - 目标是 `\\服务器\共享\…` 网络路径时，**不要默认判定为坏**，单独分成一组
    「可能是没连网，删除前自己确认」；
  - UWP / 商店应用的快捷方式**目标为空**但带 `AppUserModelID`，**不是坏的**（判据：有 AppUserModelID 就跳过）；
  - 指向可移动盘（U 盘没插）的也单独一组；
  - 快捷方式本身可能带参数和工作目录（`IShellLink::GetArguments`），别把参数当成路径的一部分。
- **hint 草稿**：`找出指向"已经不存在的程序"的桌面 / 开始菜单快捷方式，确认后清掉`
- **about 草稿**：`装过的软件卸载了，桌面和开始菜单上还留着点了没反应的图标。\n用法：点它 → 只读扫描一遍 → 列出目标已经不存在的快捷方式 → 你勾选要清的，删到回收站（不是永久删除）。\n指向网络共享的会单独列出来，因为那可能只是现在没连网，不是坏的。`

### 2.5 空文件夹清理

- **按钮**：`tools\cleanup.json`，`segment: 3`，`order: 30`，`id: empty-folders`，
  `name: 空文件夹清理`，`kind: builtin`，`module: app`，`action: emptyfolders`。
- **窗口**：选一个根目录 → 只读扫描 → 列出**空文件夹**（含"里面只有空文件夹"的，从最里层往外算）→
  勾选 → 删除到回收站（空的文件夹进回收站是没意义的，可以**先问用户**要不要直接删除；
  按本项目的口径，默认还是回收站 + 清楚说明）。
- **命令行**：`emptyfolders <目录> [--delete] [--json] [--depth=N]`，默认只列不删。
- **边界**：**不跟 junction / 符号链接**（会跑到别的盘去删东西）；跳过
  `$Recycle.Bin`、`System Volume Information`、`Windows`、`Program Files*`（除非用户显式给了这个根）；
  隐藏文件算不算"有东西"要写在说明里（默认算，即隐藏文件也算占用）；被占用 / 无权限的**跳过并列出来说明**；
  根目录自己不删。
- **hint 草稿**：`找出某个文件夹里"里面什么都没有"的空目录，确认后清掉`
- **about 草稿**：`清理旧照片、旧项目之后，会剩下一层套一层的空文件夹，手动找很烦。\n用法：点它 → 选一个文件夹 → 只读扫描 → 列出空目录（包含"里面只有空目录"的）→ 勾选后删到回收站。\n不会跟着快捷方式跳到别的盘上删东西；隐藏文件也算"里面有东西"，所以不会误删藏了文件的目录。`

### 2.6 屏幕取色器

- **按钮**：`tools\system.json`，`segment: 3`，`order: 50`，`id: color-picker`，
  `name: 屏幕取色器`，`kind: builtin`，`module: app`，`action: colorpicker`。
- **窗口**：点按钮 → 全屏半透明遮罩**覆盖所有显示器**（`SystemInformation.VirtualScreen`）→
  鼠标位置实时显示放大镜（放大 8×）+ 像素坐标 + `HEX` / `RGB` / `HSL` 值 →
  左键取色（写剪贴板 + 提示卡）→ 滚轮切换格式 → `Esc` 退出。
- **命令行**（这条是给自动测试用的，必须有）：`pick --decode=#1A2B3C` /
  `pick --decode=26,43,60` → 打出 HEX / RGB / HSL 三种表示。
  **颜色换算必须是独立静态方法**（窗口和命令共用），这样自动测试能真验。
- **边界**：多屏（可能是负坐标）；DPI 缩放（`SetProcessDpiAwareness`，别取错像素）；
  遮罩窗口不能抢焦点也不能出现在截图里；`Esc` 一定要能退出（别做成关不掉的）；Win7 上也要能跑。
- **hint 草稿**：`在屏幕上取一个像素的颜色，复制成 HEX / RGB / HSL`
- **about 草稿**：`做图、配网页颜色的时候，想拿屏幕上某个点的准确色值。\n用法：点它 → 整个屏幕变暗、鼠标旁边出现放大镜 → 移过去、左键一下就取到了（自动进剪贴板）→ Esc 退出。\n支持多显示器和缩放屏幕；只读取屏幕像素，不抓图、不保存、不上传。`

### 2.7 端口 & 进程查看

- **按钮**：`tools\system.json`，`segment: 3`，`order: 60`，`id: port-view`，
  `name: 端口与进程`，`kind: builtin`，`module: app`，`action: ports`。
- **窗口**：列出**正在监听的 TCP / UDP 端口** → 协议 / 本地地址 / 端口 / PID / 进程名 / 进程路径 /
  是否签名 → 搜索框（按端口或进程名过滤）→ 右键菜单：`复制这一行` / `打开文件所在位置` /
  `结束这个进程`（要 `ConfirmForm` 二次确认 + 保护名单）。
- **实现建议**：`GetExtendedTcpTable` / `GetExtendedUdpTable` P/Invoke（`src\Native.cs` 已有一批 P/Invoke 可参考），
  拿进程路径用 `QueryFullProcessImageName`（拿不到就说明"需要管理员才能读路径"，**不要为了读路径就去提权**）。
- **命令行**：`ports [--json] [--port=8080] [--pid=1234]`。默认表格，`--json` 给机器读（测试用它）。
- **边界**：**保护名单**（和 `src\AutoUnlock.cs` 同一份口径）：`System` / `Idle` / `csrss` / `wininit` /
  `services` / `lsass` / `smss` / `explorer` / 工具箱自己 —— 这些**不允许结束**，只显示；
  结束失败（权限不够）要说清原因；UDP 是"无连接"，列出来时别写成"正在监听连接"。
- **hint 草稿**：`看看哪个程序占着哪个端口（含进程名、路径），能定位占用者`
- **about 草稿**：`程序报"端口被占用"、或者想知道某个端口是谁在听的时候用。\n用法：点它 → 列出正在监听的所有端口和对应的程序 → 在搜索框里打端口号或程序名就能筛出来 → 确认确实是自己不要的程序了，可以在这里结束它。\n系统关键进程（System、explorer 等）只显示、点不动。结束程序不会保存对方的数据，请先自己确认。`

### 2.8 重复文件查找

- **按钮**：`tools\cleanup.json`，`segment: 3`，`order: 40`，`id: dup-files`，
  `name: 重复文件查找`，`kind: builtin`，`module: app`，`action: duplicates`。
- **窗口**：选一个（或几个）目录 → **三档比较**（先比大小 → 再比前 4KB 的 SHA256 → 最后全文件 SHA256 定案，
  这样几千个文件也很快）→ 结果按组显示（每组一个"内容完全相同"的文件集合）→
  每组**自动标出建议保留的一个**（规则可切换：最早修改的 / 路径最短的 / 保留最上层目录里的）→
  勾选后删除到回收站（**必须有确认框，并打出"将释放 X MB"**）。
- **命令行**：`dup <目录…> [--min-size=1MB] [--full] [--json]`，默认只列不删。
- **边界**：**硬链接（hardlink）不算重复**（是同一份数据，删一个不省空间，要单独标注）；
  不跟 junction；`--min-size` 默认给个下限（比如 1MB），否则小文件太多没意义；
  扫描中要能取消；进度要写出来（大目录可能几十秒）。
- **hint 草稿**：`找出内容完全相同的重复文件（先比大小再比哈希），确认后清理`
- **about 草稿**：`同一个安装包、同一张照片存了好几份，占空间又乱。\n用法：点它 → 选目录 → 先比大小、再比哈希，确认内容真的一样才归为一组 → 每组建议保留一份 → 你确认后删到回收站。\n只按内容判断，不看文件名；硬链接（同一份数据的两个名字）会被单独标出来，因为它其实不占两份空间。`

### 2.9 批量重命名（最难，放最后）

- **按钮**：`tools\cleanup.json`，`segment: 3`，`order: 50`，`id: batch-rename`，
  `name: 批量重命名`，`kind: builtin`，`module: app`，`action: rename`。
- **窗口**：选一批文件 → 规则面板（前缀 / 后缀 / 查找替换 / 序号（起始值、位数、位置）/
  正则替换（带捕获组）/ 扩展名大小写 / 用日期替换）→ **实时预览"旧名 → 新名"对照表** →
  `执行` 前先检查冲突 → 执行后写一份**撤销记录**到 `%LOCALAPPDATA%\Mxx1Toolbox\rename-<时间>.json` →
  窗口里给一个「撤销上一次重命名」按钮。
- **命令行**：`rename <目录> --prefix=照片_ --index=1 --digits=3 [--ext=jpg] [--regex=…] [--apply]`，
  **默认 dry-run（只打印对照表）**，`--apply` 才真改。
- **边界（交互细节最要命）**：
  - **预览和执行必须走同一份规则引擎**（同一份代码算名字，否则"预览说这样、执行变那样"就是 bug）；
  - 目标名已存在 → 拒绝并列出冲突，不许覆盖；
  - 只改名字不改内容、不移动文件；扩展名默认不动；
  - 文件名里 Windows 不允许的字符（`\ / : * ? " < > |`）要挡掉；
  - 一次几百个文件要有进度；撤销记录要能还原（包括中途失败的部分）。
- **hint 草稿**：`按你定的规则批量改文件名，改之前先看新旧对照表，还能撤销`
- **about 草稿**：`给一整批照片、素材改名（加前缀、加序号、替换文字）手打不可能。\n用法：选一批文件 → 设规则 → 窗口里先看清楚"旧名 → 新名"的对照 → 没问题再执行。\n执行前会检查有没有重名冲突（有就拒绝，绝不覆盖）；只改文件名，不动内容、不移动文件；执行过一次之后可以一键撤销。`

## 4. 交卷前跑什么（别跑全套）

```powershell
cd D:\萌新工具开发\toolbox

# 1) 只跑你新开的那一组（几秒～几十秒）
powershell -ExecutionPolicy Bypass -File tests\Test-Cli.ps1 -Only U      # 换成你的组字母

# 2) 改过界面的话，加跑界面那一组（真的会弹窗口，需要交互式桌面）
powershell -ExecutionPolicy Bypass -File tests\Test-Gui.ps1 -Only C      # 或你新加的界面组

# 3) 提交前闸门：它自己读 git 改动 → 只跑被影响的那几组（通常十几秒）
powershell -ExecutionPolicy Bypass -File tools\Test-Quick.ps1
powershell -ExecutionPolicy Bypass -File tools\Test-Quick.ps1 -List      # 只看看它会跑什么
```

- 第 3 步会自动带上 L0（编码 + 内联体检）与编译，**是提交前的必跑项**。
- **全套（`Test-Cli.ps1` 不带参数 + `Test-Gui.ps1` 不带参数）只在两处跑**：
  ① 用户明确要求；② 准备发版本之前。日常别跑 —— 命令行全套约 95 秒、界面全套约 145 秒。
- 改动碰到公共区（测试文件头、挑组机制、夹具、映射表）时闸门会**主动退回全套**并打印原因，这是设计如此。

## 5. 交付物长什么样

每做完一件，交这些东西：

1. 代码：`src\*.cs`（或只改 `tools\*.json` 的脚本型按钮）；
2. 按钮清单条目（**含 `hint` + `about` 两层文案**）；
3. 图标 PNG（由 `tools\Make-Icons.ps1` 生成，别手画）；
4. 测试：新组 + 界面回归项 + `test-map.json` 规则；
5. 文档：`CHANGELOG.md` `[未发布]`、`docs\DESIGN.md` 一小节、计数同步；
6. **一段提交信息，四段式**：改了什么 / 为什么 / 我验了什么 / **我没验什么**；
7. **一句"我怎么验的"**：跑了哪几组、多少项、通过多少、有没有人工看过窗口（截图路径）。

**不要做的**：不要改 `docs\DISCLAIMER.md`（改它 = 所有用户的同意指纹作废，会被要求重新确认一次）；
不要动别人的功能；不要顺手升级版本号（版本号只由 `src\AssemblyInfo.cs` 一个地方定，发版是用户决定的事）；
不要把 `bin\` 里的 exe 提交进仓库（已 gitignore）。
